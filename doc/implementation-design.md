# Concoct implementation design

Revision 0.8 · 2026-10-22 · Active handoff design

Concoct coordinates one roadmap task at a time. Reagent selects, engineers, verifies, documents and commits the work. Iragent independently assesses one exact candidate. Concoct invokes each agent, streams its prose, routes a small structured result and enforces execution bounds. Source and current project documents define implemented behavior; agent summaries are claims, not controller assessments.

## Repository and task selection

A plain `concoct run` starts in the operator's current checkout. With no active run, it requires a clean named parent branch and records its commit. The initial reagent turn examines `AGENTS.md`, `roadmap.md`, `capabilities.md`, relevant design and source, selects one suitable ready task with delivered dependencies, creates and switches to its task branch, then continues engineering in the same turn. A claim means the reagent has selected work and created its branch and external evidence. It establishes no exclusive task or session ownership. There is no host claim callback or separate selection turn.

The reagent maintains `task.md` outside the product repository under Concoct's evidence root. It records scope, decisions, progress, checks, self-review, candidate commit and next action. It keeps a task branch clean after committing. Reagent decides acceptance coverage, check sufficiency and documentation judgment. Concoct does not stage files, create a candidate commit, classify deliverables or parse task evidence to authorize a handoff. A no-work result ends selection without inventing a task. A genuine blocker is reported as an explicit question.

## Independent review and current slice boundary

A completed, schema-valid `ready_for_review` result identifies the selected task and candidate commit. Concoct records the reported identity, checks that the checkout is on a distinct clean task branch at that commit descended from the parent baseline, and requires a readable external task evidence file before starting a separate iragent session in the same checkout. No other Concoct agent runs concurrently in that checkout. The iragent receives the task, exact commit, base and evidence path, reviews source and criteria independently, and writes `review-01.md` outside the product repository. It does not modify the candidate while reviewing.

The iragent returns an approved or changes-requested result that explicitly matches the selected task and candidate commit, with summary, findings and evidence path. Concoct requires a readable external review file before displaying its location and preserves the narrative without grading it. On requested changes, reagent receives the assessment and findings, commits a distinct corrected candidate, and iragent reassesses it. Completed assessments use numbered external review files. Concoct does not decide whether findings are justified or resolved.

An approved assessment displays the task, exact commit, role summaries and review location, then waits for `concoct run --approve COMMIT` when an invocation remains. If the limit is exhausted, the approval is retained for inspection without offering an unusable authorization. Authorization must name that independently approved commit. Concoct then prompts reagent to check the source and parent binding, perform a guarded local fast-forward of the exact commit, and report its result. Reagent performs the Git operation; Concoct does not implement a separate integration transaction. No step pushes or publishes.

## Execution and state

One foreground Go binary talks to the locally verified Linux Codex 0.147.0 app-server over stdio. Each role has explicit model, reasoning effort, full-access sandbox and never-approval settings. The provider-recommended model is the default; default efforts are medium for reagent and high for iragent. Reagent and iragent use separate sessions, reused across completed turns when available. An unavailable session can be replaced using current source and external task/review evidence. Sessions are convenient continuity, not task ownership.

Concoct keeps only repository and task identity, parent and candidate commits, role settings/session IDs, current step, latest result, invocation count and an in-flight turn marker in an external atomic state file. The marker and increased count are saved before each provider turn. If execution ends without a recorded result, a later `run` reports an uncertain turn and stops for source/evidence inspection instead of dispatching another agent. An execution lock prevents simultaneous coordinator runs. Agent-maintained Markdown holds engineering and review narrative. Concoct checks evidence files for readable external regular-file presence without parsing their content. No `claim_task`, `save_checkpoint` or `save_assessment` callbacks are part of the workflow. Concoct does not reconstruct historical callback evidence or replay interrupted work automatically.

The shared provider response schema requires all declared object properties and closes additional properties. Optional values use nullable types. A result carries disposition, summary, task ID, candidate commit, findings, evidence path and an optional blocker question. Concoct validates routing fields and exact candidate identity; it treats narrative as opaque. Ordinary agent messages stream as prose with role labels and blank lines between messages. JSON-shaped message fragments are buffered until a completed item identifies a commentary envelope or final result. A commentary envelope displays its human summary, regardless of an intermediate disposition; only completed role results route the workflow. Ordinary prose and code examples remain visible. Final agent results and Concoct coordination carry separate source labels. Explicit `--json` output remains available.

The dedicated provider process writes startup and execution stderr to an external per-execution diagnostic file beside Concoct state. Normal terminal output reports that path without streaming raw provider diagnostics. Provider and process outcomes, rather than error-looking log lines, determine execution failure. On failure, Concoct gives a concise explanation and retains detailed diagnostics in that file. Quiet mode suppresses progress while retaining normal result and coordination summaries.

A run defaults to twelve agent invocations and three completed independent assessments. Fresh-run settings may choose lower or higher positive limits without resetting consumption during continuation. Reagent corrections, reviewer reassessments, replacement-session turns and integration turns consume the same invocation allowance. Optional elapsed-turn and inactivity timeouts apply to each turn; stopping invokes provider interruption, background-terminal cleanup and checks owned process cessation. A failed launch, malformed result or exhausted limit is reported clearly while retaining source and external state. An explicit blocker is shown as an ordinary question; `run --answer TEXT` sends the answer to the requesting role. Completed handoff boundaries can resume in a later invocation. Ambiguous in-flight execution remains stopped for inspection; no general recovery subsystem or old-run migration is added.
