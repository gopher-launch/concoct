# Concoct implementation design

Revision 0.8 · 2026-10-22 · Active handoff design

Concoct coordinates one roadmap task at a time. Reagent selects, engineers, verifies, documents and commits the work. Iragent independently assesses one exact candidate. Concoct invokes each agent, streams its prose, routes a small structured result and enforces execution bounds. Source and current project documents define implemented behavior; agent summaries are claims, not controller assessments.

## Repository and task selection

A plain `concoct run` starts in the operator's current checkout. With no active run, it requires a clean named parent branch and records its commit. The default authoritative backlog is repository-root `roadmap.md`; `run --roadmap PATH` selects another roadmap, with relative paths resolved from the repository. Concoct validates and records its canonical path before dispatch, supplies its contents and applicable capability-document path to every role, and prevents continuation from switching the recorded roadmap. A sibling `capabilities.md` applies when present, otherwise the repository-root document applies. The initial reagent turn examines applicable instructions, the selected roadmap and capabilities, relevant design and source, selects one suitable ready task with delivered dependencies, creates and switches to its task branch, then continues engineering in the same turn. A claim means the reagent has selected work and created its branch and external evidence. It establishes no exclusive task or session ownership. There is no host claim callback or separate selection turn.

The reagent maintains `task.md` outside the product repository under a compact evidence namespace derived from the canonical selected-roadmap path, then the task ID. Reviews use numbered files in the same namespace. This keeps identical task IDs from different roadmaps distinct without introducing the broader artifact hierarchy planned separately. Concoct verifies evidence only at these exact derived paths, while treating their Markdown contents as opaque. The reagent records scope, decisions, progress, checks, self-review, candidate commit and next action. It keeps a task branch clean after committing. Reagent decides acceptance coverage, check sufficiency and documentation judgment. Concoct does not stage files, create a candidate commit, classify deliverables or parse task evidence to authorize a handoff. A no-work result ends selection without inventing a task. A genuine blocker is reported as an explicit question.

## Independent review and current slice boundary

A completed, schema-valid `ready_for_review` result identifies the selected task and candidate commit. Concoct records the reported identity, checks that the checkout is on a distinct clean task branch at that commit descended from the parent baseline, and requires a readable external task evidence file before starting a separate iragent session in the same checkout. No other Concoct agent runs concurrently in that checkout. The iragent receives the task, exact commit, base and evidence path, including the original scope and acceptance criteria retained before the candidate removes the completed roadmap entry. It reviews source and criteria independently and writes `review-01.md` outside the product repository. It does not modify the candidate while reviewing.

The iragent returns an approved or changes-requested result that explicitly matches the selected task and candidate commit, with summary, findings and evidence path. Concoct requires a readable external review file before displaying its location and preserves the narrative without grading it. On requested changes, reagent receives the assessment and findings, commits a distinct corrected candidate, and iragent reassesses it. Completed assessments use numbered external review files. Concoct does not decide whether findings are justified or resolved.

An approved assessment displays the task, exact commit, role summaries and review location, then waits for `concoct run --approve COMMIT` when an invocation remains. If the limit is exhausted, the approval is retained for inspection without offering an unusable authorization. Authorization must name that independently approved commit. Concoct then prompts reagent to check the source and parent binding, perform a guarded local fast-forward of the exact commit, and report its result. Reagent performs the Git operation; Concoct does not implement a separate integration transaction. No step pushes or publishes.

An accepted `integrated` result completes the handoff without another agent turn. Concoct writes an idempotent external completion record containing the task, exact candidate, approval, review and evidence references, then atomically releases active state. `status` displays the latest completion when no task is active. A later plain `run` starts with fresh limits from the current clean named checkout; a descendant commit added after integration is a valid new baseline. If completion-record maintenance fails, the integrated state remains retryable and no new task starts.

## Execution and state

One foreground Go binary talks to the locally verified Linux Codex 0.147.0 app-server over stdio. Each role has explicit model, reasoning effort, full-access sandbox and never-approval settings. The provider-recommended model is the default; default efforts are medium for reagent and high for iragent. Reagent and iragent use separate sessions, reused across completed turns when available. An unavailable session can be replaced using current source and external task/review evidence. Sessions are convenient continuity, not task ownership.

Concoct keeps repository and task identity, parent and candidate commits, role settings/session IDs, current and pending steps, latest result, invocation count and an in-flight turn marker in an external atomic state file. The marker, increased count, exact provider/owned-process identities and a pre-turn checkpoint of branch, HEAD, Git-visible source and external evidence are saved before dispatch and refreshed as events arrive. Completed handoffs move to compact external completion records rather than remaining active. If execution ends without a recorded result, a later plain `run` reports the stopped turn and does not dispatch another agent. An execution lock prevents simultaneous coordinator runs. Agent-maintained Markdown holds engineering and review narrative. Concoct checks evidence files for readable external regular-file presence without parsing their content. No `claim_task`, `save_checkpoint` or `save_assessment` callbacks are part of the workflow. Concoct does not reconstruct historical callback evidence.

`run --recover` is the explicit replacement-turn boundary for `execution_failed` and `execution_uncertain`. Under the execution lock it establishes the pending step from structured state, requires the recorded processes to be terminated or observably absent, compares current source/evidence to the pre-turn checkpoint and records an audit before starting a fresh role session. It never resets or cleans source. Partial review files are moved to unique archive names before a replacement assessment, and only a valid verified review result consumes an assessment. Review recovery requires the exact clean candidate; integration recovery accepts only the unchanged task ref and a parent at either the recorded base or authorized candidate, then directs reagent to reconcile before acting. A recovery-specific model/effort choice is provider-validated and changes only the replacement role. Records too old to contain a process/checkpoint binding are refused rather than inferred.

The shared provider response schema requires all declared object properties and closes additional properties. Optional values use nullable types. A result carries disposition, summary, task ID, candidate commit, findings, evidence path and an optional blocker question. Concoct validates routing fields and exact candidate identity; it treats narrative as opaque. Ordinary agent messages stream as prose with role labels and blank lines between messages. JSON-shaped message fragments are buffered until a completed item identifies a commentary envelope or final result. A commentary envelope displays its human summary, regardless of an intermediate disposition; only completed role results route the workflow. A result is announced after its task, candidate, source and evidence bindings pass the applicable handoff checks; phase-less final results use the same boundary. Ordinary prose and code examples remain visible. Agent results and Concoct coordination carry separate source labels. Explicit `--json` output remains available.

The dedicated provider process writes startup and execution stderr to an external per-execution diagnostic file beside Concoct state. Normal terminal output reports that path without streaming raw provider diagnostics. Provider and process outcomes, rather than error-looking log lines, determine execution failure. On failure, Concoct gives a concise explanation and retains detailed diagnostics in that file. Quiet mode suppresses progress while retaining normal result and coordination summaries.

A run defaults to twelve agent invocations and three completed independent assessments. Fresh-run settings may choose lower or higher positive limits without resetting consumption during continuation. Reagent corrections, reviewer reassessments, replacement-session turns and integration turns consume the same invocation allowance. When an allowance is exhausted, Concoct retains the pending workflow step and reports each exhausted consumed/total count. The operator may authorize a strictly higher total with `--approve-review-limit-increase TOTAL`, `--approve-invocation-limit-increase TOTAL`, or both. The complete request is validated and the previous and new ceilings are durably recorded under the execution lock before dispatch; all consumed counts and workflow context remain unchanged. Work continues only when every applicable allowance permits it, and exact-commit integration still requires its separate approval.

Optional elapsed-turn and inactivity timeouts apply to each turn; stopping invokes provider interruption, background-terminal cleanup and checks owned process cessation. A failed launch, malformed result or exhausted limit is reported clearly while retaining source and external state. An explicit blocker is shown as an ordinary question; `run --answer TEXT` sends the answer to the requesting role. Completed handoff boundaries can resume in a later invocation. Ambiguous in-flight execution remains stopped until the operator requests recovery and the recorded safety bindings pass; no old-run migration is added.

## Active source and future work

The repository retains its module identity and license. The active source is authoritative. CON-042 remains a frozen historical reference and is not merged into the active tree. The old Concoct skill, self-hosting workflow, repository-local operational notes and generated templates are outside the rebuild. Construction uses ordinary manually directed Codex sessions and independent review.
