# AGENTS.md

Concoct is a Go CLI that coordinates one bounded roadmap task through reagent implementation, independent iragent review and correction, and operator-authorized local integration. Read active source, tests, `README.md` and `capabilities.md` for delivered behavior. `doc/implementation-design.md` explains the handoff design; `roadmap.md` contains future work only. Historical branches and commits are reference material, not active implementation.

Work on one task ID at a time. Before editing, read its scope, dependencies and acceptance criteria, and retain the original task specification in external task evidence so review can use it after roadmap reconciliation. For new work, use a clean named parent checkout and create a task branch in that checkout. Keep the candidate focused and committed with a clean branch. Reagent owns selection, engineering, proportionate checks, self-review and documentation judgment. Iragent independently reviews the exact commit in the same checkout without changing it. Resolve findings on the same task branch and seek another assessment. Independent approval and explicit operator acceptance of the exact commit precede local integration. Do not push or publish as part of integration.

Reconcile documentation in the candidate for its intended post-integration state. Summarize delivered behavior and practical limits by capability in `capabilities.md`; remove the completed task from `roadmap.md`, remove only dependency references satisfied by that delivery, and promote newly eligible tasks when appropriate. Preserve the IDs, scope and acceptance criteria of unfinished tasks. Retire epic or feature entries when they no longer organize unfinished work. A task with no remaining prerequisites uses `Depends on: none`. Do not copy completed acceptance criteria into `capabilities.md` or maintain a completed-task ledger there. The roadmap parser still accepts older delivered entries and capability ID headings for compatibility; that does not change the future-only maintenance rule.

Keep manual construction plans, decisions, checks and review records outside this repository under `$HOME/.concoct/manual/<task-id>/`. Concoct-run agents use the selected external evidence root, with a `task.md` checkpoint and numbered review files for each task. Do not put operational `notes.md` or task evidence in the product tree. Concoct verifies task, source, execution, evidence and approval bindings; it does not grade engineering narrative or require verbatim roadmap prose in a claim. An agent-owned task claim is evidence of selection, not an exclusive session or host callback.

For Go changes, run `gofmt` on changed Go files, `go test ./...`, `go vet ./...`, `go build ./cmd/concoct`, and `git diff --check`. Run focused CLI smoke checks when CLI behavior changes. For documentation-only changes, check links, examples, consistency with source and whitespace. Add checks when a task changes a build or test contract.

Use ordinary manually directed implementation and independent review sessions while constructing Concoct. The runner is not used to build itself. The retired Concoct skill, persona handoffs, `.concoct/current/` notes, self-hosting workflow and generated init templates are outside this construction workflow.
